## Walk results
- BOLA/BFLA: single local principal, no roles or tenants; every ID is regex-validated (`^[A-Za-z0-9_-]{1,64}$`). Accepted by design.
- Authn: bearer token on every route including `/health`, constant-time compare (`security.token_ok`); token generated by the Tauri host, passed by env, never logged or persisted. Tested: missing/wrong token returns 401.
- Mass assignment / data exposure: pydantic `extra="forbid"` on all bodies (422 tested); responses are explicit dicts.
- Resource consumption: 1 MB body cap on both Content-Length and chunked paths (413 tested), resolution <= 4096, samples <= 1024, queue <= 20, one Blender at a time, 600 s timeout, cancel kills the process tree (orphan test).
- Paths: server derives every path from validated IDs; `safe_join` rejects `..`, absolute and escaping paths. ZIP entry names are checked and re-checked on read-back. `open_folder` (Rust) only opens folders inside the CozyVerse data directory.
- Subprocess: Blender and `taskkill` run from argv lists, no shell; the spec is passed as a JSON file.
- CORS: explicit origins, no credentials; OpenAPI/docs endpoints disabled.

## Residual risks (accepted for Phase 0)
1. Blender detection executes `blender.exe` from `PATH`, `CV_BLENDER` or the saved setting (`--version`). A planted `blender.exe` earlier on `PATH` would run as the user. Mitigation later: only probe Program Files plus the user-saved path.
2. Dev origins (`localhost:1420`) stay in the CORS allow-list in release builds. They still require the token; remove in the packaged build.
3. Any process running as the same user can read the session token from the worker environment.
4. Job failure messages include the tail of Blender output (local paths) and go only to the authenticated local UI.
5. Release builds cannot yet find a bundled worker; the dev path resolves the repo `.venv` via `CARGO_MANIFEST_DIR`.

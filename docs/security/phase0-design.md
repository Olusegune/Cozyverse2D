# Phase 0 security design (rafter-secure-design walk)

Surface: local HTTP worker, Blender subprocess, file paths, ZIP export, JSON ingestion.

## Data flow and trust boundaries
```
[Tauri/React UI] --(1)--> [Python worker 127.0.0.1] --(2)--> [Blender subprocess]
                                  |--(3)--> [SQLite + project dir]    |--(4)--> [ZIP export]
```
1. UI to worker: loopback only, random port, per-session bearer token, strict CORS.
2. Worker to Blender: argv list, no shell, spec JSON written by worker into the job dir.
3. Worker to disk: every path derived server-side from validated IDs under the project root.
4. Export: names sanitized, read back and checked for zip-slip.

## Decisions
- Auth: `secrets.token_urlsafe(32)` generated by the Tauri host, passed to the worker via stdin or env, compared with `hmac.compare_digest`. All routes, including `/health`, require it. Token never logged.
- Binding: `127.0.0.1` only. CORS allows only the Tauri origin and the dev origin.
- Schemas: pydantic models with `extra="forbid"`, IDs match `^[A-Za-z0-9_-]{1,64}$`, numeric ranges bounded, request body capped at 1 MB.
- Paths: the client never supplies a file path. Resolved paths must be inside the project root (`is_relative_to` after `resolve`).
- Blender: executable path is user config, must exist and be named `blender.exe`/`blender`. Spec passed as a JSON file, never interpolated into a command line. Blender scripts never execute user-supplied code. Imported `.blend` or mesh files are Phase 1 and require confirmation.
- Jobs: one Blender process at a time, hard timeout, cancel kills the process tree, output written to temp then atomically renamed.
- Export: archive names are relative, no `..`, no duplicates; readback verifies SHA256 and that every entry stays inside the extraction root. Manifests validated against `schemas/*.json`.
- Secrets: no provider keys in Phase 0. Phase 2 stores them in the OS credential vault, never in manifests or logs.
- Telemetry: none.

## Abuse twins
- "Render five views" becomes unbounded queued jobs: queue depth and one-Blender-at-a-time cap.
- "Export project" becomes path traversal via asset name: IDs are regex-restricted and names slugged.
- Another local process calls the worker: bearer token plus loopback plus CORS.

## Residual risks (accepted for Phase 0)
- Any process running as the same user can read the token from process memory or environment. Accepted for a desktop tool.
- Blender itself is trusted software chosen by the user.
